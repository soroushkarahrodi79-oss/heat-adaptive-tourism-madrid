# PHASE2_SOLWEIG_METHOD.md — HATI-Madrid Phase 2

Version 1.0 · 2026-08-17. Records the exact software, environment, inputs,
parameters, and workflow used to run SOLWEIG for this phase, per the task's
explicit requirement. **The SOLWEIG algorithm itself was not modified.**

---

## Software

| Field | Value |
|---|---|
| Package | `solweig` (official UMEP-dev standalone Python package, `https://github.com/UMEP-dev/solweig`) |
| Version | **0.1.0b92** (confirmed via `solweig.__version__` and recorded in every run's `run_metadata.json`) |
| Backend | Rust compute core (`rustalgos`) with a Python API; rasterio for GeoTIFF I/O (no QGIS dependency) |
| Installation method | `pip install solweig` |
| Python | 3.12.10, in a **dedicated virtual environment** (`.venv_solweig/`) created specifically for this phase, because the project's default Python (3.14.5) is incompatible — every published `solweig` release on PyPI caps at `Requires-Python <3.14` (confirmed: `pip install solweig` under 3.14.5 fails with "Could not find a version that satisfies the requirement"; the same command under 3.12.10 succeeds, resolving `solweig-0.1.0b92-cp311-abi3-win_amd64.whl`) |
| Key dependencies installed alongside | `rasterio 1.5.1`, `numpy 2.5.2`, `pyproj 3.7.2`, `shapely 2.1.2` (pinned by `solweig`'s own requirements), plus `pvlib` (added separately for the clear-sky irradiance estimate, see below) |
| UTCI computation | SOLWEIG's own built-in `solweig._utci` module, invoked automatically when `outputs` includes `"utci"` — see `docs/PHASE2_UTCI_METHOD.md` |

## Computational environment

Windows 11, local machine (no cloud/HPC resources used). GPU auto-detection
is a feature of this SOLWEIG build (`GPU_ENABLED`, `is_gpu_available()`) but
was not specifically configured; the run log shows `[GPU] GVF GPU context
initialized` / `[GPU] Anisotropic sky GPU context initialized`, i.e. the
package auto-dispatched to whatever compute backend was available. All
three timesteps together (633×749 pixel grid, 2.5 m resolution) completed
in under 5 seconds of actual computation.

## Input preprocessing

See `docs/PHASE2_INPUT_FEASIBILITY.md` for full source provenance. Summary
of the processing chain (`src/build_solweig_geometry.py`):

1. Fetch DEM (5 m), building nDSM (2.5 m), vegetation nDSM (2.5 m) from the
   real IGN/CNIG WCS services, clipped directly to the study-area bbox.
2. Fix the malformed `LOCAL_CS` CRS tag both services return, re-tagging to
   proper EPSG:25830 (a metadata correction — no coordinate values altered;
   see `docs/PHASE2_INPUT_FEASIBILITY.md` for the diagnostic).
3. Resample the DEM from its native 5 m onto the building/vegetation
   layers' native 2.5 m grid (bilinear; a smooth, low-frequency surface, so
   upsampling introduces negligible artefact — the 2.5 m grid is the
   authoritative working resolution for the whole pipeline, chosen so no
   resampling loss falls on the two geometrically decisive layers).
4. Clip both nDSM layers to ≥0 (LiDAR speckle noise below ground is
   possible in normalized products; negative values have no physical
   meaning for a height-above-ground field and are set to 0).
5. Compose: `dsm = DEM + building_nDSM` (absolute elevation, ground+building
   surface, `dsm_relative=False`); `dem = DEM` (absolute elevation, bare
   earth); `cdsm = vegetation_nDSM` (height above ground,
   `cdsm_relative=True`, SOLWEIG's own default convention for this input).
6. `land_cover` and `tdsm` (trunk-zone height) are **not** supplied —
   `tdsm` is auto-generated by SOLWEIG from the CDSM using its default
   `trunk_ratio=0.25` (documented in `SurfaceData.prepare()`'s own
   docstring); `land_cover` absence is the documented simplification noted
   in `docs/PHASE2_INPUT_FEASIBILITY.md`.

## Meteorological forcing construction

`src/build_met_forcing.py`. Real observed Ta/RH/wind/pressure from
Madrid/Barajas (`data/raw/episode_aug2023_barajas_raw.csv`, same source used
throughout this project) for the exact three canonical timestamps
(12:00/15:00/18:00 local, 2023-08-21). Global horizontal irradiance is
**estimated** via `pvlib.location.Location.get_clearsky(..., model="ineichen")`
— pvlib's implementation of the Ineichen-Perez clear-sky model with the
package's bundled real Linke-turbidity climatology, evaluated at the study
area's real centroid coordinates and the true UTC timestamps. This is used
because Barajas' hourly archive has no pyranometer column, and is justified
by the archive's own confirmed clear-sky weather code (`coco=1`) at all
three target hours — checked programmatically (`assert (obs_df["coco"]==1).all()`)
before the clear-sky model is invoked, not assumed.

Resulting forcing (`data/raw/phase2_met_forcing.csv`):

| Local time | Ta (°C, real) | RH (%, real) | Wind (m/s, real) | Pressure (hPa, real) | GHI (W/m², **estimated**) | Solar elevation (°) |
|---|---:|---:|---:|---:|---:|---:|
| 12:00 | 34.2 | 28.0 | 2.61 | 1016.6 | 722.8 | 48.6 |
| 15:00 | 38.8 | 21.0 | 1.00 | 1013.8 | 861.9 | 60.2 |
| 18:00 | 40.5 | 17.0 | 2.11 | 1011.6 | 497.7 | 33.9 |

## SOLWEIG execution workflow

`src/run_solweig.py`. Each of the three timestamps is run as an
**independent single-timestep calculation** (not a continuous timeseries),
because they are three hours apart and every prior phase of this project
has treated them as independent snapshots, not a series with meaningful
inter-hour accumulation.

```python
surface = solweig.SurfaceData.prepare(
    dsm="data/interim/solweig/dsm_2m5.tif",
    cdsm="data/interim/solweig/cdsm_2m5.tif",
    dem="data/interim/solweig/dem_2m5.tif",
    working_dir="data/interim/solweig_cache/",
    dsm_relative=False, cdsm_relative=True,
)
location = solweig.Location.from_surface(surface, utc_offset=2, altitude=650.0)

for each timestamp:
    weather = solweig.Weather(datetime=..., ta=..., rh=..., global_rad=..., ws=..., pressure=...)
    summary = solweig.calculate(
        surface=surface, weather=weather, location=location,
        output_dir=f"data/interim/solweig_cache/run_{label}/",
        outputs=["tmrt", "utci", "shadow"],
    )
```

**Relevant parameters** (recorded automatically by SOLWEIG in each run's
`run_metadata.json`, package defaults - not overridden by this project):
`use_anisotropic_sky=true` (anisotropic, not uniform, sky diffuse radiation);
`conifer=false` (deciduous transmissivity assumed); tree shortwave
transmissivity 0.03 (leaf-on) / 0.5 (leaf-off), trunk ratio 0.25, leaf-on
season day-of-year 97–300 (i.e. the model correctly treats 21 August, day
233, as leaf-on — appropriate for the real August date); standing-posture
human geometry (`Fside=0.22, Fup=0.06, height=1.1 m, Fcyl=0.28`); default
material set (cobblestone, dark asphalt, building roofs, unmanaged grass,
bare soil, water, brick/concrete/wood walls) — **not** overridden with a
custom `land_cover` grid (see input-feasibility doc). No parameter was
tuned to produce a particular result; every value above is the package's
own documented default.

## Raw outputs preserved

Per-timestep raw GeoTIFFs (not the multi-timestep aggregate — since each
run is a single timestep, `tmrt_mean`/`tmrt_day_mean` and the raw
per-timestep file are numerically identical, but the raw file is the
correct artefact to preserve):

- `data/interim/solweig_cache/run_{1200,1500,1800}/tmrt/tmrt_20230821_{HHMM}.tif`
- `data/interim/solweig_cache/run_{1200,1500,1800}/utci/utci_20230821_{HHMM}.tif`
- `data/interim/solweig_cache/run_{1200,1500,1800}/shadow/shadow_20230821_{HHMM}.tif`
- `data/interim/solweig_cache/run_{1200,1500,1800}/run_metadata.json` (SOLWEIG's own self-documented run record, quoted above)

Copied (CRS-corrected — see input-feasibility doc for the same LOCAL_CS
issue recurring on SOLWEIG's own output) to the required deliverable
locations: `outputs/maps/{tmrt,utci}_{1200,1500,1800}.tif` (+ rendered
`.png` via `src/make_thermal_maps.py`).

## Known package-documented limitation (quoted, not discovered by this project)

SOLWEIG's own `calculate()` docstring states: *"Modelled downwelling
longwave (L↓) carries a known +18 to +55 W/m² positive bias that traces to
the Jonsson et al. (2006) formulation... K↓ at any single pixel is
shadow-edge-sensitive and may spike on a single mis-aligned hour;
spatially-averaged K↓ has much lower error."* This is carried forward as a
first-class caveat in `docs/PHASE2_VALIDATION_REPORT.md` — the software's
own documented behaviour, not a limitation this project needed to discover
independently, and a further reason the pre-registered 10 m buffer MEAN
(not a single centroid pixel) is used as the primary asset-exposure
statistic.
